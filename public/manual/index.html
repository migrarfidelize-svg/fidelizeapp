Como usar este manual

Siga as seções na ordem do menu lateral. Marque “Concluí esta etapa” ao final de cada passo — a barra de progresso é salva no seu navegador, então você pode fechar e continuar depois.

Transparência: o esquema de banco, as policies, funções, triggers, índices e buckets deste manual foram extraídos automaticamente do banco real conectado ao projeto na data acima. Nada foi inventado.

1. Requisitos

Tudo o que você precisa ter em mãos antes de começar.

🔐 Conta na Supabase obrigatório

Gratuita para começar. É onde ficam banco de dados, autenticação, arquivos e tempo real.

🟩 Node.js 20 ou superior obrigatório

Baixe em nodejs.org (versão LTS). Verifique com node -v.

📦 Gerenciador de pacotes

npm (vem com o Node) ou bun. Os comandos deste manual usam npm.

🌐 Navegador recomendado

Chrome, Edge ou Firefox atualizados. Safari 16.4+ para notificações push no iPhone.

💻 Máquina

4 GB de RAM (8 GB recomendados), 2 GB livres em disco e conexão estável.

🧰 Opcionais

Git, VS Code, domínio próprio com HTTPS (necessário para push e PWA em produção).

Serviços externos opcionais

O sistema instala e roda sem eles, mas alguns módulos ficam inativos:

  • Mercado Pago ou Asaas — cobrança de planos e PIX dos anúncios.
  • Google AI Studio (Gemini) — assistente Fidê e Inteligência de Cardápio.
  • Cloudflare Turnstile — captcha no login/cadastro em desktop.
  • Chaves VAPID — notificações Web Push (geradas localmente, sem custo).
  • Apple / Google Wallet — passes na carteira do celular.
Extensões de banco necessárias: pg_cron, pg_net, pg_stat_statements, pgcrypto, supabase_vault, uuid-ossp. Todas são criadas pelo próprio SQL e estão disponíveis na Supabase.

2. Passo a passo completo da instalação

Dez etapas, do zero ao sistema rodando. Escrito para quem nunca usou Supabase.

1

Criar conta na Supabase

A Supabase é o serviço que hospeda o banco de dados, a autenticação e os arquivos do sistema. É a única conta obrigatória.

  1. Acesse supabase.com e clique em Start your project.
  2. Entre com GitHub ou com e-mail e senha.
  3. Confirme o e-mail, se solicitado.
Dica: use um e-mail corporativo permanente — a conta será a dona do banco de produção.
Atenção: guarde a senha em um gerenciador de senhas. A recuperação de projetos perdidos é trabalhosa.
2

Criar um novo projeto

  1. No painel, clique em New project.
  2. Name: por exemplo fidelize-producao.
  3. Database Password: gere uma senha forte e salve-a — ela não é exibida novamente.
  4. Region: escolha a mais próxima dos seus usuários (para o Brasil, South America (São Paulo)).
  5. Clique em Create new project.
Boa prática: crie dois projetos — um de teste (-dev) e um de produção. Nunca teste no banco real.
3

Aguardar a criação do banco

A Supabase leva de 1 a 3 minutos para provisionar o banco. Enquanto o indicador estiver em Setting up project, alguns menus ficam indisponíveis.

Possível erro: se o projeto travar em "Setting up" por mais de 10 minutos, recarregue a página; persistindo, exclua e crie novamente em outra região.
4

Abrir o SQL Editor

  1. No menu lateral do Supabase, clique em SQL Editor.
  2. Clique em New query.

É nesse editor que todo o banco do sistema será criado, em uma única execução.

5

Executar o SQL completo

  1. Vá até a seção 6. SQL Completo deste manual.
  2. Clique em Copiar SQL.
  3. Cole no SQL Editor da Supabase.
  4. Clique em Run (ou Ctrl/Cmd + Enter) e aguarde. Pode levar de 30 a 90 segundos.
  5. Ao final, deve aparecer Success. No rows returned.
Dica: se o editor reclamar do tamanho, execute por blocos, sempre na ordem das seções numeradas do arquivo.
Importante: execute somente em um projeto novo e vazio. O script é idempotente (if not exists), mas rodar sobre um banco já usado pode gerar avisos de objetos duplicados.
6

Configurar o Storage

O SQL já cria todos os buckets e as permissões de arquivo. Confirme em Storage no menu lateral.

  • Se algum bucket não aparecer, crie manualmente com exatamente o mesmo nome (veja a seção 7. Storage).
  • Todos os buckets do sistema são privados: o acesso é feito por URLs assinadas geradas pelo próprio sistema.
Erro comum: "Bucket not found" ao subir um logo significa bucket ausente ou com nome divergente.
7

Copiar as chaves da Supabase

  1. Vá em Project Settings → API.
  2. Copie a Project URL.
  3. Copie a chave anon / publishable.
  4. Revele e copie a chave service_role (secreta).
Segurança: a chave service_role ignora todas as regras de segurança do banco. Ela só pode existir no servidor, jamais no navegador, no Git ou em prints.
8

Configurar as variáveis de ambiente

Na raiz do projeto, crie um arquivo .env com as variáveis obrigatórias:

VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=
SUPABASE_URL=
SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
APP_URL=

A lista completa, com explicação de cada variável, está na seção 8. Variáveis de Ambiente.

Dica: em hospedagens (Vercel, VPS, Docker) cadastre as mesmas variáveis no painel do serviço, não em arquivo versionado.
Nunca envie o arquivo .env para o Git. Confirme que ele está no .gitignore.
9

Executar o projeto

Com o Node.js 20+ instalado, na pasta do projeto:

npm install
npm run dev

O terminal mostrará um endereço local (normalmente http://localhost:8080). Abra no navegador.

Para produção:

npm run build
npm run preview   # ou sirva a saída pelo seu servidor/hospedagem
Erro comum: variáveis VITE_* são lidas na inicialização e embutidas no build — alterou o .env? reinicie (ou refaça o build).
10

Verificar o funcionamento

Siga o roteiro da seção 9. Testando a instalação. Em resumo: criar conta, criar estabelecimento, carimbar um cliente e abrir o cartão pelo QR Code.

3. Configuração da Supabase

Onde encontrar cada chave e o que fazer com ela.

Project URL

Onde: Project Settings → API → Project URL.
Formato: https://xxxxxxxxxxxx.supabase.co
Vai em: VITE_SUPABASE_URL e SUPABASE_URL.

Anon / Publishable Key

Onde: Project Settings → API → anon public (ou publishable key).
Vai em: VITE_SUPABASE_PUBLISHABLE_KEY e SUPABASE_ANON_KEY.
Pode ficar visível no navegador: quem protege os dados é o Row Level Security.

Service Role Key

Onde: Project Settings → API → service_role (clique em Reveal).
Vai em: SUPABASE_SERVICE_ROLE_KEY — apenas no servidor.

Crítico: essa chave ignora todas as policies. Se vazar, qualquer pessoa lê e apaga todos os dados. Nunca commite no Git, nunca use em código de front-end.

Autenticação

  • Authentication → Providers → Email: mantenha habilitado.
  • Confirm email: o sistema foi ajustado para cadastro sem confirmação por e-mail. Se preferir exigir confirmação, ative aqui e configure o SMTP.
  • Authentication → URL Configuration: defina Site URL com o endereço público do sistema e adicione-o em Redirect URLs.
  • Google (opcional): Providers → Google, com Client ID e Secret do Google Cloud.

Rotinas automáticas (opcional)

O sistema possui rotinas de aniversário, reengajamento, fila de e-mails e ciclo de anúncios em /api/public/cron/*. Elas exigem o cabeçalho apikey com a chave publicável. Para agendar, use pg_cron + pg_net (veja o arquivo pg_cron-setup.sql na pasta /public do projeto).

9. Solução de Problemas

Os erros mais comuns, com causa, diagnóstico e solução.

relation "public.xxx" does not exist

Causa: O SQL foi executado fora de ordem ou parcialmente.

Como identificar: O erro aponta uma tabela que ainda não existe.

Solução: Execute o arquivo SQL completo, de cima para baixo, em um projeto novo.

type "public.xxx" already exists

Causa: O SQL foi executado duas vezes.

Como identificar: Mensagem de tipo/objeto duplicado.

Solução: Ignore com segurança ou recrie o projeto Supabase e rode uma única vez.

permission denied for table ...

Causa: Faltaram os GRANTs da seção 8 do SQL.

Como identificar: Erro 401/403 vindo da API do banco.

Solução: Rode novamente a seção 8. GRANTS do arquivo SQL.

new row violates row-level security policy

Causa: O usuário logado não tem permissão pela policy, ou não está autenticado.

Como identificar: Erro ao salvar dados no painel.

Solução: Confirme que você está logado e que o usuário é membro do estabelecimento (establishment_members).

Invalid API key / JWT malformed

Causa: Variáveis de ambiente erradas ou trocadas.

Como identificar: Falha em toda a comunicação com o banco.

Solução: Revise VITE_SUPABASE_URL e VITE_SUPABASE_PUBLISHABLE_KEY e reinicie o servidor (variáveis só são lidas na inicialização).

Tela branca após o build

Causa: Variáveis VITE_* ausentes no momento do build.

Como identificar: Console do navegador mostra erro de undefined.

Solução: Defina as variáveis antes de rodar npm run build e refaça o build.

Upload de imagem falha (bucket not found)

Causa: Os buckets não foram criados.

Como identificar: Erro 404 no Storage.

Solução: Rode a seção 10. STORAGE do SQL ou crie os buckets manualmente com os mesmos nomes.

Notificações push não chegam

Causa: Chaves VAPID ausentes, site sem HTTPS ou permissão negada.

Como identificar: O contador de inscritos fica em zero.

Solução: Gere as chaves VAPID, use HTTPS e reautorize as notificações no navegador.

Assistente de IA offline

Causa: GEMINI_API_KEY não configurada no servidor.

Como identificar: Badge "offline" na Fidê.

Solução: Configure a chave e reinicie o servidor.

Pagamento aprovado mas plano não liberou

Causa: Webhook não está chegando ao servidor.

Como identificar: Sem registro em payment_logs.

Solução: Cadastre a URL pública de webhook no gateway e confira o segredo do webhook.

Erro de porta em uso ao rodar npm run dev

Causa: Outro processo usa a porta.

Como identificar: EADDRINUSE.

Solução: Feche o outro processo ou rode npm run dev -- --port 8081.

10. Perguntas frequentes

Preciso pagar a Supabase para rodar o sistema?

Não para começar. O plano gratuito da Supabase atende testes e operações pequenas. Para produção com muitos clientes, recomenda-se o plano Pro (backups diários e mais recursos).

Posso usar outro banco que não seja Supabase?

Não sem alterações profundas. O sistema depende de recursos específicos: autenticação Supabase, RLS, Storage, Realtime e funções em PL/pgSQL.

O SQL deste manual apaga dados existentes?

Não. Todos os comandos usam if not exists / on conflict do nothing. Ainda assim, execute sempre em um projeto novo e vazio.

Posso executar o SQL em partes?

Pode, desde que respeite a ordem das seções (extensões → tipos → tabelas → constraints → índices → funções → triggers → grants → RLS → storage → dados iniciais).

Como crio o primeiro Super Administrador?

Crie a conta normalmente pela tela de cadastro e depois rode no SQL Editor: insert into public.app_roles (user_id, role) select id, 'super_admin' from auth.users where email = 'seu@email.com';

As chaves publicáveis podem ficar visíveis no navegador?

Sim. A chave anon/publishable foi feita para isso — quem protege os dados é o RLS. Já a service_role nunca pode sair do servidor.

Preciso configurar e-mail?

Só se quiser enviar e-mails transacionais. Sem isso, o sistema funciona, mas a fila de e-mails fica parada.

As notificações push funcionam no iPhone?

Sim, a partir do iOS 16.4, e apenas quando o app é instalado na tela de início (PWA).

O que acontece se eu não configurar o gateway de pagamento?

O sistema funciona, mas nenhum plano poderá ser assinado. Você pode liberar acessos manualmente pelo painel do Super Administrador.

Como faço backup?

Supabase → Database → Backups. No plano gratuito, faça exportações periódicas por conta própria.
